# M2A aura refresh eligibility: static review

This note covers only the pinned client `fae13d1d0a7683726db520ec5c687d67d701c874a5708aeb9bff6eaacf2f054c` disassembly’s periodic Tower morale refresh. It does not infer a King location, cached morale value, or a future world state.

## Exact scheduler

`World::tick_before_inputs` (`0x19b86`) increments the World `u16` at context offset `45084` by one, at `0x19ba5–0x19bb1`, when the World is initialized. The Tower pass then iterates chunk-map results (`func2014`, `0x108e5d–0x108eed`). The first returned word is retained at scratch `+180`; the second is the chunk pointer at `+184`. The pass reads the first word’s low `u16` as `var19`, and reads the chunk pointer’s `+36` as the Tower-slot vector bounds (`0x1a42f–0x1a4a0`). The aura gate uses:

```text
(present_tower_rank XOR ((world_u16_tick + chunk_result_low_u16) & 0xffffffff)) & 15 == 0
```

The actual instructions are `var4 XOR var30; 15; and; eqz` at `0x1a4ce–0x1a4f0`; `var30` was formed from the World counter and the chunk result’s low `u16` at `0x1a449–0x1a4a0`. Only the low four bits affect the test, so the condition is equivalently equality of the low nibbles. This gate reads the World counter and chunk-iterator result; it does not read a per-Chunk tick field.

`var4` is a dense rank among present Tower actors, not the Tower’s local slot number. The counter is reset for each chunk at `0x1a473–0x1a477` and incremented once for each non-null result from `func2290` at `0x1a4ce–0x1a4d8`. `func2290` scans 48-byte slots in order, skips entries whose first word is `0x80000000`, and returns the next populated Tower (`0x111744–0x1117d4`). `RelativeTowerId::upgrade` maps the slot ordinal’s row and column bits into the Tower ID (`0x142448–0x14246c`), but that ID does not encode the dense rank when earlier slots are empty. A Tower ID’s low coordinate bits alone therefore cannot establish the refresh phase.

When the gate is true, the routine initializes the result to false, checks owner ID, and may compute the player’s cached-Ruler adjacency; it then stores the result into Tower byte `+45` at `0x1a4f2–0x1a561`. Owner zero skips the King lookup and stores false. The periodic eligibility gate itself does not depend on Tower kind or owner. A newly captured Tower is consequently subject to the same gate on a later `tick_before_inputs`; its new owner does not force an immediate refresh in the capture input that follows that tick pass.

## What a before snapshot can prove

For one next `tick_before_inputs`, an exact-rank proof is sufficient if the evidence establishes the `world_u16_tick` value before its increment, the chunk iterator result low `u16`, the target Tower’s dense present-Tower rank in that chunk, and the Tower identity/slot through the pass. Evaluate using `world_u16_tick + 1` modulo the `u16` clock before the low-nibble test. The eligibility gate is the same for owned, unowned, and newly captured Tower types, provided the actor remains in the iterator. At the gate’s scheduled phase, an unowned Tower is explicitly written false; owner-unknown does not make a scheduled refresh safe to ignore. Exact rank is not necessary for every exclusion; the rank-interval certificate below can prove a gate miss without resolving hidden occupancy.

The ordinary visible-actor snapshot does not establish the exact dense rank unless it proves the complete present-Tower set and iteration order for that entire chunk, across all owners. Missing/hidden actors may occupy earlier slots and shift the rank. A visible-world-complete claim scoped to the player’s visible refs is not a proof of all-owner chunk occupancy. Without a complete chunk actor set, exact eligibility may remain unknown; the interval test below can still prove that a particular phase cannot refresh. Do not infer exact rank from ownership or King coordinates.

The canonical decoder can map its tick field to the scheduler clock only through the pinned pointer layout: the decoded root’s World pointer is at `root+648`, and `World+45084` aliases the singleton tick at `root+45732`. This establishes which observed field corresponds to the World counter; the scheduler itself still adds the chunk key low `u16` before testing the Tower rank.

### Conservative rank-interval certificate

Complete chunk occupancy is stronger than necessary for some one-pass exclusions. `func2290`’s slot ordinal is the input to `RelativeTowerId::upgrade` (`0x111744–0x1117d4`, `0x142448–0x14246c`). That conversion places the ordinal’s upper nibble in the local row and lower nibble in the local column on the 16×16 Tower grid, added to `ChunkId::bottom_left` (`0x14b55e–0x14b575`). The chunk-map iterator’s returned key is the same chunk identifier passed as the iterator’s `+12` base into `func2290` and then into `RelativeTowerId::upgrade`; the scheduler separately uses that key’s low `u16` as its phase addend. Thus for a target at row-major local slot `j = 16·row + column`, the runtime rank `r` is the number of occupied slots with ordinal less than `j`, and necessarily `0 ≤ r ≤ j`.

Let `L` be the number of positively observed present Towers in this same chunk with local slot `< j`, and let `p = (world_u16_tick + 1 + chunk_key_low_u16) mod 16` for the next `tick_before_inputs` pass. If those `L` actors are proven to remain present before the scheduler reads the chunk, then `r ∈ [L,j]`; hidden occupancy can only add actors in the remaining earlier slots. The aura refresh is impossible whenever no integer `r` in `[L,j]` has `r mod 16 = p`. This is a sufficient proof even though the exact rank is unknown. If persistence of the observed prefix is not established, set `L=0`; the unconditional bound `[0,j]` remains valid as long as the target keeps the same chunk and slot. In particular, for `j<15`, this can rule out phases whose residue exceeds `j`; it does not prove no-refresh for every tick.

This is a before-snapshot eligibility theorem, not an automatic next-tick continuity theorem. Ownership changes, including capture, do not change slot rank by themselves. Unknown actors appearing/disappearing in earlier slots remain bounded above by `j`, but observed earlier actors may only contribute to `L` if their continued presence is certified through the exact pre-input scheduler pass. Target movement, destruction/replacement, or chunk reassignment invalidates the certificate. Across a horizon, the interval test proves no refresh only when every phase residue misses `[L,j]`. Every 16 consecutive stable-clock phases covers all residues, so this interval test cannot certify a full 16-pass no-refresh horizon. If the exact rank is also stable, one of those passes refreshes; with a changing rank, the interval alone does not prove that a refresh actually occurs. This still says nothing about the refreshed morale value, which depends on the player’s cached Ruler state.

For a horizon of `h` future passes, evaluate each next low-nibble clock value only while actor identity, chunk result, and dense rank are proven stable through those passes. With a stable rank and offset, the low nibble cycles through all 16 values; every 16 consecutive passes therefore include exactly one eligible refresh. A full 16-tick no-refresh claim is impossible under those stable conditions. For shorter horizons the exact phase can establish no refresh only for the checked values. Births, deaths, movement between chunks, or other slot mutations can change dense rank, so a current snapshot alone does not certify future rank stability.

## Scope limit

The only direct Tower `+45` store in `World::tick_before_inputs` is the gated store at `0x1a561`. The same Tower pass separately changes unit counts/capacity and Tower kind (`Units::capacity` around `0x1a57e–0x1a5f7`, production/type progression around `0x1a5fa–0x1a70b`, then `Tower::reconcile_units`). Thus a proven missed aura gate says only that this periodic refresh did not write the morale byte during that pass. It does not certify unchanged capacity, production, Tower kind, owner, actor presence, or state across the pass, and it does not rule out writes in other functions. Any consumer that needs a stable Tower snapshot must retain its independent full-state and chronology guards.

## Checked slot bound and helper scope

The pinned `runtime/research/v2/disassembly.json` was checked directly for the local-slot mapping. The scheduler initializes the per-chunk slot cursor to zero at `0x1a483–0x1a49c`. `func2290` scans 48-byte entries, advances the ordinal once per entry, skips the empty sentinel, and passes the resulting ordinal plus the chunk key to `RelativeTowerId::upgrade` (`0x111744–0x1117b2`). At `0x142448–0x14246f`, the conversion takes the ordinal’s upper nibble as the local row and its lower nibble as the local column, added to `ChunkId::bottom_left`. Therefore a tower at row-major local slot `j` can have dense present-Tower rank only in `[0,j]`.

The pure `no_periodic_aura_refresh` helper applies this unconditional interval to an exact pre-increment `u16` World tick, a `u16` chunk key, a local slot, and a horizon of 1–16 future passes. It returns true only if each future phase residue lies above the slot, excluding every possible present rank from the periodic gate. A true result covers only this periodic store for the same actor, chunk, and slot throughout the checked horizon. It does not certify all morale writes, the morale value, or a long-term trajectory.
