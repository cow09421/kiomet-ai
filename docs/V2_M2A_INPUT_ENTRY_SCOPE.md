# M2A input-entry evidence scope

This note bounds what a captured left-button drag can establish. Static client evidence is pinned to `runtime/research/v2/fae13d1d0a7683726db520ec5c687d67d701c874a5708aeb9bff6eaacf2f054c.wasm` (SHA-256 `fae13d1d0a7683726db520ec5c687d67d701c874a5708aeb9bff6eaacf2f054c`) and its aligned `runtime/research/v2/disassembly.json`. Broker behavior is corroborated by vendored public source at `runtime/research/v2/kodiak-source/client/src/broker/client_broker.rs`. This is source comparison, not current server authority.

The normal decoder exports a camera candidate from `root+48080`, `root+48084`, and `root+48100` in [`client_fae13.js`](../src/kiomet_ai/v2/observe/client_fae13.js#L139). In pinned `KiometGame::peek_mouse` (WASM `0x57c65`; disassembly JSON `lines[138054]`), the game object is `root+47280`; its `PanZoom` is at `+792`, with center coordinates at `+8/+12` and zoom at `+28`. `PanZoom::pan` (`0x1460bb`) and `multiply_zoom` (`0x1178aa`) use those fields. The exported triple therefore aliases the pinned render camera fields. The raw candidate is useful for endpoint projection; it does not expose the drag's saved source field.

The pinned button path is ordered `peek_mouse(Button)` before `MouseState::apply`: vendored broker `mouse()` first handles the raw mouse event, then maps `mousedown`/`mouseup` and calls the game before applying the button state ([broker lines 280–327](../runtime/research/v2/kodiak-source/client/src/broker/client_broker.rs#L280)). In `peek_mouse`, the source-start branch requires internal phase `+696 == 2`, passes the current pointer through `get_closest`, and, when that result is present, records the chosen tower at game offset `+708` and changes the phase to `1` (disassembly JSON `lines[138432..138504]`). The release branch in phase `1` consumes the saved `+708` source (same function, from `lines[138212]`). Ordinary movement updates pointer position; `MouseState::apply` (`0xfc6cf`; JSON `lines[453379..453479]`)'s move variant writes its position fields, and the pinned move path (`ClientBroker::mouse_move`, `0xef8e6`) has no `+708` store. These facts make source derivation from a down endpoint plausible when the phase and source-selection branch are known.

Those branch conditions are not fully witnessed by endpoint samples. The decoder does not export phase `+696` or active drag source `+708`; its `selected_tower` candidate reads the separate tagged field at `root+47968/+47972` ([decoder lines 257–258](../src/kiomet_ai/v2/observe/client_fae13.js#L257)), which is not evidence of the saved drag source. `get_closest` (`func 722`, disassembly JSON `lines[271611..271895]`) starts from `TowerId::closest`, enumerates a square of tower candidates, and ranks visible candidates by squared distance (`func 1344`, `lines[406305..406441]`); the complete candidate radius/packing predicate has not been qualified for this protocol. Keep handler-time source and route selection **UNKNOWN**.

The normal broker has additional ways to interrupt or synthesize the drag. `mouseleave` and window blur reset `MouseState` (broker lines 319–329); pointer-lock exit emits button-up events for held buttons (lines 501–519); touch processing can synthesize left/right button events (lines 332–343 and 400–470). The current observer (SHA-256 `9465a5c3581d6659571fa83949b90d7cb13896e6acdbba3889f4c0dd7d78ecb6`) passively invalidates on blur, mouseleave, touch, pointer-lock change, pointer cancel, visibility change, and keydown/keyup; the broker has a separate keyboard input path (lines 201–228).

There is also a concrete unqualified listener interval in the recorded zero-troop preflight `runtime/research/v2/input-entry-preflight-host1-20261002.json`: besides the observer's window capture listener, script 37 has a registered window capture callback for `mousedown`, `mouseup`, and `mousemove` (line 7994); the game broker is a canvas bubble listener (script 8, line 2270). The inventory proves registration, not that this callback executed during a gesture or affected event/world state. Its effect remains unreviewed. Do not infer that endpoint sampling is immediately adjacent to, or the only input before, the broker handler.

The endpoint validators establish fresh full-visible snapshots, trusted unmodified left-button endpoint coordinates, unique visible tower-center projections, and matching camera/canvas geometry. The direct route certificate is limited to `BEFORE_SNAPSHOT_ONLY`; both helper outputs retain gesture/route continuity as `UNKNOWN`. These checks do not prove what the handler consumed, intermediate event state, a server application tick, or a full visible-world simulation transition. Any later simulator comparison must start from the recorded before state and separately compare the complete visible world.

Finally, the host adapter attempts mouse-up in cleanup whenever mouse-down may have started. That is necessary to release the browser button, but after an exception it can complete a partially moved, unvalidated game gesture. Mark such a result `INVALID_OR_PARTIAL` and treat it as a possibly dispatched action; the receipt cannot imply that validation prevented a command.
