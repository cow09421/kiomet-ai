# M2A visible-cell absence review

**Conclusion:** Keep `PLAYER_VISIBLE_COMPLETE` fail-closed at the existing requirement that every positive sensor ref decodes to a current visible tower. No coverage change is justified by an absent chunk or tower sentinel alone.

In the pinned `client_fae13.js` decoder, each positive `Visible.refs` count increments `positiveRefs` before the code skips an absent chunk or absent tower (`client_fae13.js:146–156`). Those cases therefore reduce `towers.length` without identifying why the actor payload is absent. The extractor correctly leaves coverage `PARTIAL` when `positive_refs != decoded towers` (`extractor.py:165–177`).

The pinned disassembly confirms two separate `Option` checks. `ChunkMap::get_0` (func 2919, `0x125d24`) checks the chunk-slot tag against `0x80000000` at `0x125d60–0x125d6a` and returns no chunk when absent. `ChunkMap::get_1` (func 3665, `0x13c354`) first returns no tower when `get_chunk` is null (`0x13c363–0x13c368`), then checks the tower-slot tag against the same sentinel (`0x13c37e–0x13c388`). A missing chunk and an empty tower slot thus both surface as no tower through the getter, even though they are different storage states.

The public reference makes the distinction meaningful: `Visible.refs` stores nonzero sensor coverage, and `Visible::iter` filters those refs through `towers.get(id)` (`client/src/visible.rs:10–24`). Tower slots are `Option<Tower>` (`common/src/chunk.rs`, `Chunk`); a `None` tower slot within a present chunk is an empty actor slot in that local model. The server also filters client actor updates by an effective viewport and admits only a bounded number of previously unknown viewport chunks per update (`server/src/service.rs`, `get_game_update`). The captured state has no per-chunk freshness or synchronization evidence to establish that a missing chunk is current and authoritative.

This matches the earlier public-only review: the official iterator omits absent actors, but omission alone does not prove an empty world cell. The pinned getter disassembly clarifies that absent chunk and absent tower are distinct `Option` cases; it does not prove freshness for a missing chunk. A future absence certificate would need to expose chunk presence separately and establish that a present chunk is current at the observed tick before treating its empty tower slot as observed absence. Until then, missing positive-ref cells remain unknown and coverage remains partial.

The subsequent [concrete actor-update currentness proof](V2_M2A_ACTOR_UPDATE_CURRENTNESS.md) closes the normal network call chain and the chunk/singleton aliases in this binary. The decoder also now reports raw `CHUNK_ABSENT` versus `TOWER_NONE` diagnostics behind the same positive sensor gate. Neither change promotes an omitted actor to a canonical absence fact in this checkpoint: the complete-coverage equation remains unchanged, and a real gap's coherent present-chunk certificate still needs validation. Original PARTIAL evidence and formal corpus counts are retained.
