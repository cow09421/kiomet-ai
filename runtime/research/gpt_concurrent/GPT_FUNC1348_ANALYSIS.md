# Production func 1348（正式版函式 1348）分析

## 結論

`1348` 是 `522` 部隊相撞戰鬥使用的單位替換／消耗回呼。它與 `1347` 具有相同的五個參數、大小、單位分類、兵力扣除、last-unit（上一個投入單位）更新及 Ruler（國王）離場分支；它把事件轉送給 `2561`，而不是 1347 使用的 `2193`。

- 位置：`0x0e47ef`；大小 272 bytes（位元組）
- 簽章：`(i32, i32, i32, i32, i32) -> nil`
- 唯一直接呼叫者：`522`。
- 直接被呼叫者：`4277 Unit::is_single_use`、事件橋接 `2561`、`1448 Units::subtract`。
- 主體中沒有 `call_indirect`（間接呼叫）；`2561` 透過閉包上下文進行間接事件派送。

## 輸入、輸出與副作用

| 類別 | 靜態語意 |
|---|---|
| 輸入 | 呼叫者的戰鬥／事件旗標上下文、目前側 Units（兵力）參照、目前側 last-unit 欄位、對側上一投入單位列舉值、本次投入單位列舉值。參數角色由 `522` 的呼叫堆疊與偏移讀寫確認；除錯符號未保留 Rust 欄位名稱。 |
| 輸出 | 無回傳；修改 Units、last-unit 欄位與事件旗標，並呼叫事件橋接。 |
| 一次性單位 | enum 6／7／8 對應 Shell／EMP／Nuke；每戰同類事件旗標只允許首次事件，單位本身每次投入仍立即扣除 1。 |
| 普通單位 | 下一單位接替時才扣除上一個已投入普通單位；目前單位列舉值寫回 last-unit 欄位。 |
| Ruler | 非一次性；被取代／終端整理而離場時扣除，並以對側 last-unit 作失去國王事件的原因。 |

## 事件閉包與函式指標

Production function（正式版函式）2561 與 2193 都會呼叫 `1943 CombatInfo::into_info_event`（戰鬥事件轉資訊事件），再依呼叫者閉包上下文執行 `call_indirect`（間接呼叫）。間接呼叫所需的索引／上下文由 `522` 建立的事件閉包資料供應。1348 本體沒有儲存或選擇函式指標，也沒有捕獲閉包；它只把事件種類、側別與單位資料交給 2561。此動態派送是資訊事件出口，不能把它解讀成戰鬥勝負或塔主寫回。

公開來源 `combatants.rs:135-202` 是對應的泛型閉包：辨認目前是攻方或守方，對一次性單位做消耗與單場事件去重，並在 Ruler 離場時記錄擊殺者單位。部隊碰撞外層只讓一個方向產生權威事件，避免同一場對撞重複記錄；Production（正式版）呼叫圖與此用途相符。

## 與 1347 的關係及信心

1348 不是 1347 的成功／失敗或攻／守配對；兩者是相同 callback（回呼）邏輯在不同戰鬥 wrapper（外層包裝）中的兩份編譯結果：

```text
448 塔戰      → 1347 → 2193 → 呼叫者事件閉包
788 → 522 部隊碰撞 → 1348 → 2561 → 呼叫者事件閉包
```

局部兵力、last-unit 副作用、事件轉換及 caller（呼叫者）：PASS（通過）。InfoEvent 後續如何更新玩家全域狀態屬外層事件消費器，因此鏡像仍將 Ruler（國王）與一次性單位保守回覆 `UNSUPPORTED_CASE`（不支援案例）。
