# Production func 448（正式版函式 448）分析

## 結論

`448` 是 `World::tick_before_inputs`（世界在輸入前的節拍處理），不是單一的戰鬥解析器。它在世界節拍中更新塔光環、檢查部隊抵達與路徑相撞，並在塔戰結束後完成事件、塔主、塔型、部隊與合併處理。

- Production WASM（正式版網頁組件）：SHA-256 `fae13d1d0a7683726db520ec5c687d67d701c874a5708aeb9bff6eaacf2f054c`
- 函式位置：`0x19b86`，大小 7022 bytes（位元組）
- 原始簽章：`(i32, i32, i32) -> nil`；呼叫者提供世界狀態、節拍與事件閉包所需的低階參照。正式版未保留可直接命名每個參數的除錯資訊，因此不把暫存器位置臆測成 Rust 欄位名。
- 回傳：無；所有結果以參照參數就地寫回，事件則交給呼叫者提供的事件閉包。
- 對應來源：`vendor/kiomet-ref/common/src/chunk.rs` 的 `Chunk::tick`／抵達處理，與 `combatants.rs` 的 `Combatants::fight`。這是結構對應，不是正式版執行差分。

## 呼叫關係

- 呼叫者：`443 ServerState::apply`、匿名外層驅動 `1242`。
- 塔戰：`448` 內嵌一般戰鬥迴圈，呼叫 `1778` 士氣、`2408`／`2827` 選兵、`1347` 回呼、`2022` 傷害、`3757` 整理與 `1888` 存活檢查。
- 部隊相撞：`448 → 788 → 522`。`448` 沒有直接呼叫 `522`；`788` 先處理部隊路徑／重疊與關係，再呼叫 `522`。塔戰與部隊相撞是同一節拍中的不同分支。
- 塔主與兵力寫回：`3571 Tower::set_player_id_inner`、`3107 Units::reconcile`、`2195 Units::add_units_to_tower`。
- 特殊事件：`1347 → 2193 → 1943`，事件閉包以 `call_indirect`（間接呼叫）派送；`448` 本身也以呼叫者提供的事件閉包寫出戰後事件。

## 讀取與寫入

| 範圍 | 靜態可見欄位／效果 |
|---|---|
| 塔 | 讀取單位、塔主、塔型、光環旗標、延遲、補給線與進出部隊集合；可改寫塔單位、塔主、塔型、延遲與集合。塔光環旗標位於 Tower `+45`，塔型位於 `+46`，EMP 延遲位於 `+47`。 |
| 部隊 | 讀取路徑、玩家、進度、燃料、速度、光環快照與 Units（兵力）；可消耗兵力、改路徑／進度，或將部隊從入站集合移除並重新放入路段集合。 |
| 事件 | 交戰事件、失去／取得塔、部隊消失、國王陣亡等資料交給閉包；此事件出口本身不改變戰鬥算術。 |

## 主要分支與生命週期

| 順序 | 條件與行為 | 結果 |
|---|---|---|
| 塔光環更新 | `(tower index XOR tick) & 15 == 0` 時檢查國王同塔／鄰塔，更新 Tower `+45`。派兵時 Force `+21` 保存光環快照。 | 士氣旗標不在每個戰鬥回合重算。 |
| 中立空塔 | 塔主不存在且塔兵為空時不進戰鬥解析器；存活部隊可直接設塔主，接著呼叫 `3107` reconcile（容量重整）。 | 這是直接佔領分支；完整抵達後的移動／合併仍屬外層流程。 |
| 非空塔交戰 | 塔有主人或有守軍，且兩方關係不友善時進入內嵌戰鬥。`4969(27, tower.units)` 保留塔盾；`4969(tower_type, force.units)` 移除攻塔 Force 的 Shield。之後以兩側士氣與互斥光環建立單一 signed i32（有號 32 位元）累積值。 | 依 Air（空中）再 Surface（地面）及單位順位輪流選兵；每擊呼叫 `1347` 再呼叫 `2022`。 |
| 戰鬥終端 | 尾端先整理剩餘單位，再以 `1888` 檢查兩側存活和 signed accumulator（有號累積值）。塔方是 Tower 時有防守平手規則；塔方不是 Tower sentinel（哨兵值）27 時不套用塔規則。 | 產生攻方勝、守方勝或 contested（雙方皆敗／無勝者）結果；普通兵力及塔守軍已就地變更。 |
| EMP 塔延遲 | 戰鬥暫存的「攻方 EMP」旗標成立時，寫入 `Tower+47 = max(old, 240)`。 | `Tower.delay` 倒數時會跳過該塔的兵力生產／衰減與中立塔降級；不改 Force 移動欄位。`522` 的 Force 對 Force 分支沒有這項 Tower 寫入。 |
| 塔主結算 | 攻方勝則新塔主為攻方玩家；守方勝則保留舊塔主；無勝者則新塔主為空。Production（正式版）呼叫 `3571` 寫入塔主。失去主人時逐級降塔型，並清除塔延遲。 | 中立守塔若攻方勝，直接設為攻方；敵方塔若雙方皆敗，舊塔主會清除。 |
| 抵達後部隊處理 | 空部隊丟棄；燃料用盡則過期；友軍若可續行且未撞上同目的地部隊上限 8，改放入出站／下一塔入站集合；否則友軍兵力以容量規則併入塔。 | 敵對戰後攻方殘兵可續行或併入新塔；敗方空部隊移除。友軍合併不是戰鬥結果的一部分。 |

## Owner（塔主）、Survivor（存活兵力）與 Capacity（容量）

- `448` 負責塔戰結果之後的塔主分支；勝負不是 `1347` 決定，而是戰鬥終端的存活與累積值分支決定。
- 戰鬥以參照直接改寫 Force 與 Tower 的 Units。防守存活兵力留在 Tower；攻方存活兵力留在抵達 Force，之後交給 move-on（續行）或友軍合併分支。
- 敵方佔領後，`3571` 只改塔主／補給線，不呼叫容量重整。中立空塔直佔呼叫 `3107`；友軍合併呼叫 `2195`，並依塔型容量限制加入兵力。
- 塔容量也在交戰選兵時計算 Tower 部隊是否 overflow（超容量）；這會影響空／地欄位，不是額外傷害倍率。已整理的普通容量表 22/22 列匹配參考來源；友軍合併的外層路徑不由戰鬥鏡像推算。
