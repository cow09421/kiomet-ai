# Production func 522（正式版函式 522）分析

## 結論

`522` 是 Force（部隊）對 Force（部隊）路徑相撞時的戰鬥解析器，位於 `448 → 788 → 522` 的間接呼叫路徑。它完成兩側一般戰鬥、回呼與終端存活判定，改寫兩側 Units（兵力），並把結果交回 `788`；它不負責 Tower owner（塔主）轉換。

- Production WASM（正式版網頁組件）：SHA-256 `fae13d1d0a7683726db520ec5c687d67d701c874a5708aeb9bff6eaacf2f054c`
- 函式位置：`0x68dbe`，大小 1528 bytes（位元組）
- 簽章：`(i32, i32) -> i32`；兩個參數是 `788` 建立的碰撞上下文與一支 Force（部隊）。
- 唯一直接呼叫者：`788`；`788` 的直接呼叫者為 `448`。
- 對應來源：`chunk.rs` 部隊碰撞閉包與 `combatants.rs:106-365`。

## 入口條件與戰鬥設定

`788` 先要求部隊路徑相接、方向與進度區間重疊，且兩方關係不友善；只有符合條件才呼叫 `522`。`522` 再讀路徑、進度需求、速度、玩家／兵力上下文，並以兩個 TowerType sentinel（塔型哨兵值）27 建立 Force 戰鬥端點。

- `4969(27, units)` 對兩側都不移除 Shield；這和 `448` 攻打 Tower 時移除攻方 Shield 不同。
- `1778` 分別計算兩側士氣；Force `+21` 光環快照可建立正／負單一累積初值。
- 迴圈使用 `2408`／`2827` 選兵、`1348` 做替換／消耗回呼、`2022` 算傷害；兩側共用 Air→Surface 順序和相同的 signed i32（有號 32 位元）累積器。
- 結束時呼叫 `3757` 整理兩側尾端狀態、`5202` 更新候選索引，再以 `1888` 檢查存活。

## 回傳值與 Survivor writeback（存活兵力寫回）

`522` 對兩個 Units（兵力）參照直接扣除兵數；最後把「入站 Force 是否由 Attacker（攻方）勝出」寫入 `788` 的存活旗標。回傳 i32 布林值為「另一側／Defender（守方）是否勝出」，讓 `788` 決定是否保留被碰撞的出站 Force。

這個方向可由 `522` 尾端的 `result == 0` 寫入入站存活旗標、`result == 1` 作回傳值，以及 `788` 依回傳值保留／移除向量項目交叉確認。雙方皆敗時不保留任何一方。這是 wrapper（外層包裝）要的保留判斷，不是玩家或 Tower owner（塔主）欄位。

## 哪些是、哪些不是

| 問題 | 判定 | 證據 |
|---|---|---|
| Battle finalization（戰鬥最終判定） | PASS（通過）：完成 Force 對 Force 的終端存活／勝方分支。 | `1888`、signed accumulator 與返回標籤，對應來源 `Combatants::fight`。 |
| Owner transition（塔主轉換） | 不屬於此函式。 | 沒有 Tower owner、Tower type 或 `3571` 寫入；只有部隊碰撞上下文。 |
| Survivor writeback（存活兵力寫回） | PASS（通過）：兵力就地修改並寫入入站存活旗標。 | `1348`／`1448`／`3757` 與尾端旗標。 |
| Force removal（部隊移除） | 由 `788` 完成。 | `788` 依 `522` 布林結果移除出站敗方，再依入站存活旗標決定是否保留入站部隊。 |
| Special cleanup（特殊清理） | PARTIAL（部分完成）：局部消耗與事件旗標由 `1348` 執行；外層事件閉包目標仍是上下文提供的間接派送。 | `1348 → 2561`，其中含 `call_indirect`（間接呼叫）。 |
| Tower EMP delay（塔的 EMP 延遲） | 不會寫入。 | `522` 不讀寫 Tower `+47`；該分支只在 `448` 的塔戰。 |

## 448 與 522 的精確關係

`448` 沒有直接呼叫 `522`。它呼叫 `788` 檢查世界中的 Force（部隊）相撞；`788` 在符合路徑重疊與敵對關係時呼叫 `522`。同一個 `448` 另有獨立的 Force-vs-Tower（部隊對塔）內嵌戰鬥，該路徑使用 `1347`，不是 `522`。

鏡像已把普通 Force-vs-Force（部隊對部隊）納入支援子集；路徑重疊的時序、同節拍多場碰撞順序仍由呼叫端提供，不能從本函式單獨推算。
